# Workspace instructions

The app is called **duna** (lowercase everywhere, from 2026-09-30; it was "Subtítol Live"). Code, targets and folders keep the `SubtitolLive` names. Bundle ID `com.uriocallaghan.duna` (iPhone, Mac store app and their extensions), app group `group.com.uriocallaghan.duna`. The App Store name needs a suffix ("duna: live captions"), since "Duna" is taken. The store listing texts are in `docs/APP-STORE-FITXA.md`, the founder's upload steps in `docs/PUBLICAR.md`.

## Delivering duna changes

For every user-requested change that affects `SubtitolLive`, deliver the installed app as part of the same task:

1. Run the relevant tests, including `xcrun swift run -c debug SubtitolLiveTests` for application behavior.
2. From `SubtitolLive/`, run `./scripts/build-app.sh`. A Swift build inside `.build/` alone is not a user-visible delivery.
3. Verify `/Applications/duna.app` is validly signed and its code (`codesign -dvvv` CDHash) matches the newly staged bundle.
4. Relaunch the installed app so the user is testing the new version.

The change is complete only when the installed app has been updated and verified. If installation cannot finish, report explicitly that the change exists only in source/build output.

## iPhone app (`SubtitolLive/iOS`)

The iPhone app compiles the shared modules and a listed subset of `Sources/SubtitolLive` (the `includes:` list in `project.yml`; the Mac store target takes the whole folder) with its own screens in `iOS/SubtitolLiveiOS`. `docs/IPHONE.md` covers the design, the App Store checklist and the debug launch arguments.

- `project.yml` is the source of truth. XcodeGen rewrites `Info.plist` and the `.entitlements` files from it, so Info.plist keys and entitlements go under `info.properties` / `entitlements.properties` there.
- Build and run: `SubtitolLive/scripts/build-ios-app.sh` (runtime via `build-ios-runtime.sh`, models via `stage-ios-resources.sh`).
- Shared files stay platform-neutral: fonts go through `PlatformFont`, colours through `ReadingTheme`, and anything AppKit or UIKit sits behind `#if canImport(AppKit)` / `#if os(iOS)`. A change to a shared file is a Mac change too, so the Mac delivery steps above apply.
- The simulator slice of `Vendor/RuntimeiOS/NemoSpeechRuntime.xcframework` runs on the CPU (the Simulator's Metal aborts in ggml's host buffers) and `Bridge.c` asks for the CPU there. The simulator cannot open the Mac's microphone, so transcription is checked with `SUBTITOL_REPLAY_AUDIO=<wav>` (Debug only), which plays a file through the capture path at real-time pace.
- Deliver an iPhone change by building it, then checking it in the simulator with screenshots, including partway through every transition it touches. Screenshots are too slow to catch a transition's first frames: record it (`xcrun simctl io booted recordVideo`, stopped with SIGINT) and look at the frames (`ffmpeg -vf fps=60`). Send simulator taps one per turn, since taps sent together land at once. Screens use the debug launch arguments `-autoInstall ca`, `-autoRecord YES`, `-openPanel <item>` and `-openSheet <sheet>`.
- Languages are listed under `languages` in `ModelManifest.json` (`stage: beta` shows the Beta label). Each is a folder `<id>/…` (speech model + compiled punctuation model) that `LanguagePackStore` finds in three places, in this order: inside the app (`Languages/<id>` in the bundle, filled by the `BUNDLED_LANGUAGES` list of `project.yml`'s "Bundle languages" phase and of `build-app.sh`; empty by the founder's decision of 2026-10-07, the app must stay small), Apple-hosted Background Assets packs (`AppleHostedPackSource`), and our mirror (`MirrorPackSource`: the same `.aar` as a GitHub release asset, `languages[].mirror` with the archive's SHA-256, tried when the App Store's lookup takes over 15 s, or its download throws or shows no progress for 20 s while the app is active; the App Store's download is dropped first with `remove(assetPackWithID:)`, bounded to 5 s, so the two never run together; the download holds a background task (`BackgroundTime`) and, cut off, resumes from its resume data when the app is active again (`PackDownload`, 3 times); unpacked with AppleArchive into Application Support, which is excluded from backups (iOS Data Storage Guidelines; the flag did not take on the sandboxed Mac, harmless there) and swept of `.<id>-<UUID>` leftovers at launch). App Review's network often cannot fetch Apple-hosted packs (Developer Forums thread 815174); build 6 of the Mac app was rejected for exactly that on 2026-10-06, hence the mirror. A bundled language, if ever listed, is never downloaded or removed (`isBundled`, `isRemovable`). `stage-ios-resources.sh --asset-packs` writes the `.aar` archives for App Store Connect and the mirror; after rebuilding them, update `mirror.sha256`/`bytes` in the manifest and the release asset. Debug builds also copy `.work/ios-packs` into the app as `DevPacks`, and the store installs from there, so a phone can be tested before the packs are uploaded; `-packSource store` (Debug) ignores DevPacks and `SUBTITOL_PACK_MIRROR=<base URL>` points the mirror at a local `python3 -m http.server`. Install on the connected iPhone with `xcodebuild … -destination id=<udid> -allowProvisioningUpdates` then `xcrun devicectl device install app`.
- Five languages: ca, es, gl, eu, en. Each one is a speech model plus `LanguageRules` (SubtitolCore): number rules (`NumberNormalizing`: `CatalanNumbers`, `SpanishNumbers`…), ordinary words, and the ¿¡ openings. Text only settles through a punctuation predictor, and the manifest decides which one:
  - ca and eu have their own Core ML model (`catala-puntuacio`, `euskara-puntuacio`);
  - es, en and gl use recognisers that write their own marks (`writesPunctuation: true`). `RecognizerPunctuation` strips the marks before the stabiliser and hands them back by audio span, taken from the newest window that heard the word well inside;
  - a language with neither falls back to `PlainPunctuation`.
  `CatalanElisionRepair` runs only for ca (`ASREngine(repairsCatalanElisions:)`). The harness takes `--language xx --recognizer-punctuation`. `.work/lang-spike/tools/harness_pc.sh` scores the formatted text, and the README there has the model choices and their numbers.

## Motion principle

duna is smooth and animated everywhere; this is a basic product principle, not polish. No visible state change may snap: themes, panels, the settings bar, text roll-up, and anything new. The one exception is on purpose: a word the recogniser revises swaps in place, because moving it would draw the eye to something that means nothing (see `FixedFocusTranscriptView`). Under Reduce Motion, movement becomes a cross-fade; it never becomes a jump.

- Colour changes that `Text` or AppKit-backed views don't interpolate on their own go through an animated value. The theme is an example: `ContentView.themeDarkness` (0 light, 1 dark) animates, `ThemeBlend` re-renders each frame, and `ReadingTheme.blended` / `SettingsBarPalette.blended` mix every colour.
- Check a new transition by taking screenshots partway through it. Seeing only the final state doesn't show whether it snapped.

## Web demo (Català ASR)

`web/` is a zero-dependency PWA that streams Catalan speech to Deepgram (nova-3, `language=ca`) for live transcription. Deployed to https://asr.uriocallaghan.com (Netlify site `catala-asr`).

- Deploy: `cd web && netlify deploy --prod` (the dir is already `netlify link`ed). Env-var changes require a redeploy to reach the function.
- `functions/dg-token.mjs` mints 120 s grant tokens via `POST api.deepgram.com/v1/auth/grant`; the browser opens the Deepgram WebSocket itself with `['bearer', jwt]`. `DEEPGRAM_API_KEY` lives only in Netlify env vars and needs **Member** permissions.
- Credits: client-side VAD gates audio (only voiced seconds are sent; silence is free KeepAlive frames), 60 s of silence or a hidden tab → full sleep. Facts: `docs/deepgram-research.md`.
- Audio path: `worklet.js` (same-origin AudioWorklet: VAD gate + 16 kHz resample + level ×6 like the app). The AudioContext is recreated after `getUserMedia` if its rate differs from the mic's (iOS silence bug).
- Layout mirrors the desktop app: portrait = shader band on top, reader below; landscape = 68/32 like `ContentView`. The shader is a WebGL2 port of `ProceduralNoise.metal`.
- Debug on a phone: open `/?debug` for a live overlay (stage, AudioContext, WebSocket close code, VAD, seconds sent). `/?lvl=0.8` fakes voice level for the shader.
- `sw.js` is network-first; bump `CACHE` when the shell file list changes.
- Icons are generated: `python3 scripts/generate-web-icons.py`.

- The Mac gets its languages as packs too. `build-app.sh` (the ad-hoc local build) bundles `.work/ios-packs` as `DevPacks`, and the bar's language card (`LanguagePanel`) installs from there. The Mac App Store app has `com.apple.security.network.client` only for the mirror. `LanguageSession` (SubtitolLiveApp.swift) rebuilds the `SubtitleController` whenever the language changes.
- The Mac App Store build is the `SubtitolLiveMac` target in `iOS/project.yml`. It shares one App Store record, and one bundle ID (`APP_BUNDLE_ID`), with the iPhone app. It is sandboxed, requires macOS 26, and links the runtime statically (the `macos-arm64` slice from `build-ios-runtime.sh`). The build and the account steps are in `.work/MAC-APP-STORE-BUILD.md`.
- Punctuation, capitals and digits are always on. `TranscriptFormatter` (SubtitolCore) freezes each word's formatting once it is committed and three more words have been heard (or the speaker pauses after it), strictly in order. Its output marks as committed only words whose text is final (frozen, and not inside a number still open), so `RollUpTranscriptLayout` places every settled word once, already punctuated: re-placing settled text is what made read lines jump (821–2,643 line jumps per recording before, 0 after; see `docs/LECTURA.md`). `PunctuationModel` (SubtitolPunctuation, Core ML) is our Catalan model in `models/catala-puntuacio/` (6-bit `.mlpackage` + `vocab.json`, `merges.txt`, `labels.json`), pinned file by file under `punctuation` in the manifest; it returns per-word probabilities (`PunctuationPrediction`), and `labels(for:)` is the model's own argmax. `build-app.sh` compiles it to `.mlmodelc` with `SubtitolPunctuationCheck compile` (no Xcode needed). Digits follow ésAdir via `CatalanNumberNormalizer`. `SubtitolPunctuationCheck tokens|labels|numbers` reproduces the parity checks against the Python reference (`.work/tools/itn_ca.py` for numbers).
- Pauses come from the audio, never from recogniser timestamps (two recognisers disagreed by ~0.2 s on the same gap). `SilenceTracker` (10 ms frames, floor = 10th percentile of the last 8 s, silent below floor + 12 dB, runs ≥ 80 ms) is fed every live snapshot on the coordinator's `stateQueue`; `LiveRecognitionUpdate.silences` carries its `SilenceMap` to the formatter. `PauseEvidence` adds pause log-odds to the model's sentence-end probability; a sentence end followed by ≥ `paragraphPause` (0.5 s) of silence, or any pause ≥ `lineBreakPause` (1.0 s), sets `startsParagraph`, which the layout turns into a new line. Settled text is memoised in the formatter (`settledText`, `absorbed`): the stabiliser keeps a bounded window, and re-reading a number after its first word scrolled out used to print "2020 1020 20" and rebuild the reading pane. `.work/tools/vad_causal.py` is the same detector in Python; `pause_calibrate.py` fits the `PauseEvidence` constants against punctuated references from harness `--decisions-out` logs.
- A new voice starts a new paragraph, in any language. `SpeakerTurnTracker` (SubtitolCore) keeps the last 10 s resampled to 16 kHz and asks for an analysis every 0.5 s; `SpeakerSegmentationModel` (SubtitolSpeakers) runs pyannote segmentation-3.0 (MIT, 5.7 MB Core ML in `models/veus-segmentacio`, pinned under `speakers` in the manifest, made by `scripts/convert-speaker-model.py`, 53,010/53,010 frames equal to ONNX Runtime) on `RecognitionCoordinator.speakerQueue`, off the recogniser's GPU. A change needs ≥ 0.6 s of each voice around it and two windows agreeing; short replies and overlap never open a paragraph. `SpeakerChangeMap.turnStarts` puts each change on the nearest gap between two words; the formatter counts the end of a turn as a paragraph pause (it favours a full stop) and waits to freeze the last word of a turn until the detector has settled the audio after it, unless the detector is more than 3 s behind. Without the model the text runs on as before. The harness takes `--speakers models/veus-segmentacio`.
- `SilentWordFilter` (SubtitolCore) drops recognised words with no audible sound around them: the loudest 10 ms frame from 50 ms before to 250 ms after the word must stand ≥ 10 dB over the window's quietest tenth of frames (padding excluded). The Conformer writes "muy"/"más" into digital silence and steady noise, and invented phrases into laptop room tone; it also stamps a phrase-initial word 60–100 ms before its sound, hence the asymmetric search. `RecognitionCoordinator` applies it to live and final results (rebuilding the text from the kept words, so the text-only fallback cannot restore them) and the harness does too. Since 2026-10-14 the voice detector overrules it where it has listened: `SpeakerTurnTracker` keeps where pyannote heard a voice (`SpeechPresenceMap`, newest analysis of a frame wins, 60 s kept), and `voicedWords(_:energyKept:)` keeps a word with a voice under it whatever the energy said and drops one where nobody spoke (100 ms head and tail); the energy test decides only where the detector has not listened yet (the last ~0.5 s, the first 2 s). In a reverberant hall the gaps stay loud and real words failed the energy test (41% omissions on `.work/venue-test`'s `sala`), while applause and a crowd's murmur passed it. `SubtitolEngineIntegrationTests` checks silence and noise at -45…-70 dBFS for 4–8 s windows. Steady loud noise (fan, traffic, a video's noise bed) swings 8–13 dB per 10 ms frame, so a frame also counts as voice when it stands ≥ 5 dB over the floor and its pre-emphasised level (0.97, averaged over 30 ms) rises ≥ 5× the noise's own spread (min 1.5 dB) over that level's floor (`VoiceThresholds`, shared with the importer's hole test): 15GdH3 at 5 dB SNR 25.5% → 14.1% WER, clean audio unchanged, noise-only files still give no words.
- `ReadableTranscriptStabilizer.observe` takes the window's start (`windowStartSequence`). With it, a response that has nothing where words heard in two earlier windows were (well inside the window) is set aside unless the hole persists: RNNT decoders sometimes return only the words after a pause, and committing those used to lose the rest for good. Separately, a word still undecided `maximumUndecidedSeconds` (2.5 s) after it ends is decided by votes: every form heard at that place counts (`Candidate.votes`, grouped by accent-free key, inherited by a new word at the same place or at a place dropped before), and the policy's `overdueEvidenceRequired` says how many hearings the most frequent form needs to be committed (Immediat 2; Fiable and Equilibrat `never`: the word is dropped once heard `overdueHearingsToJudge` = 4 times, and the words after it go on). Until 2026-10-14 the word was committed "as last heard", which on 87 ParlamentParla clips was wrong 142 times and right 63, and in a hall with an audience was most of what the reader saw ("gardinet", "avestres", "miedo"): WER 9.66% → 7.52% on those clips, wrong words 24% → 10% of the words said in the venue test's `sala`, at the price of more holes (41% → 53% omissions there, 5.1% → 6.2% on clean conversation). Judging after 4 hearings beat 2 (8.49%) and never (7.72%). Equilibrat now commits like Fiable (3 hearings, 0.65 s, hop 300 ms) and only shows the tail sooner. `docs/RELIABILITY.md` has the details; the ParlamentParla replay (`.work/tools/replay_batch.sh` over the 87 clips in `.work/parla-seg`, scored with `batch_wer.py`) is also the regression check that caught a duplicate-identity bug in the first version. At the window's left edge (its first 1.5 s, once it holds 3 s) FastConformer places old words a few frames late and stretches the last word before a silence to the window's end, so a settled word there counts as itself within 0.25 s (`leftEdgeEnd`): "para para todos." / "along? Along?" at the end of an utterance are gone, and the 87 Catalan, 60 Spanish and 60 English live replays are word-for-word unchanged. The harness prints each window's words with `SUBTITOL_TRACE_WORDS=1` and what the two filters drop with `SUBTITOL_TRACE_SILENT=1`; `--recognition-cache DIR` also works for live replays (keyed by window offset and length; the detector's answers by window end), `--policy HOP,SHOW,REPLACE,AGE,COMMIT,LAG,OVERDUE[,SHARE[,JUDGE]]` tries other thresholds and `--no-speech-gate` leaves the energy test alone. `.work/venue-test` (README in `docs/AUDITORIA-PARAULES-INVENTADES.md`) is the public-event test: EMpodcat clips through a synthetic hall with a crowd, crowd sounds alone (`sense_veu`, where every word is an invention), `run.sh`/`run-parla.sh` with per-set caches, `score.py`/`score_parla.py` with insertions, substitutions and omissions apart. Use it, with the ParlamentParla replay, for any change to the filters or the stabiliser.

- Video import (Mac gallery glyph `photo.on.rectangle` beside the share glyph, `⌘ O`, a file dropped on the window, Open With, the Dock icon, the Share menu; iPhone gallery glyph, top left (share glyph top right) → Photos or Files, "Open in" from Files, the share extension) makes a word-per-cue .srt on the device. `FileTranscriber` (SubtitolCore) cuts the recording into 14 s windows that meet at the quietest moment near their ideal length, with 1.5 s of context each side, and keeps the words whose middle lies between the cuts; everything after recognition is the live path (`SilentWordFilter`, `SilenceTracker`, `TranscriptFormatter` fed 24 words at a time so the punctuation model never exceeds its 256 tokens, `SessionTranscript`). A long window now and then comes back with a stretch of speech missing (9 s and 30 words once), which live listening never notices because it hears every word dozens of times: every gap of ≥ 0.8 s with ≥ 0.35 s of voice is heard again in 7 s windows, and only holes where that found some words go on to 10 s and 5 s windows (holes that stay empty are music or noise, and hearing them again only invented words). The Conformer now and then returns nothing for a whole window of clear speech: a window with voice and no word is heard again starting 0.5 s and then 1 s later, the lost start replaced by silence in front so its length does not change. A word counts as covering at most 1.5 s when looking for holes, because the decoder stretches the word before a skipped stretch over it ("episodiam", 4.5 s over 19 words). Together: lost stretches of ≥ 5 words 21 → 13 on the dev episodes, 16 → 9 on the sealed set. File mode punctuates with `PauseEvidence.Rule.file` (pause weighs twice as much, a voice change counts as 1 s, commas get pause evidence too); live keeps `.live`: sentence-end recall 59% → 67% on the sealed set at the same precision. The voice change detector runs on its own thread (`SpeakerPass`), beside recognition on the GPU; in series it doubled the time. Every window is widened with more of the recording to exactly its round's length (14, 7, 10 or 5 s; a clip shorter than that is padded with silence in front): the runtime builds and keeps a graph, with its buffers, for every input length it sees, and windows of a new length each time ran an iPhone out of memory at the first window (`ggml_init` abort, 6.5 GB of malloc). On `.work/clean-test` (`.work/file-import`: `run.sh TAG SET --file-mode`, `score.py SET TAGS…`) it beats the live replay: EMpodcat 12.6% vs 15.5% WER, the two Softcatalà episodes 6.3% vs 6.7%; the same word starts at the same time within 40 ms (p99) whatever the window cut. A 15-minute episode takes 30–60 s on an M3 (GPU load varies). The harness takes `--file-mode [--file-window S --file-context S]`, `--pause-rule live`, `--recognition-cache DIR` (replays formatting without the GPU) and `SUBTITOL_TRACE_HOLES=1`. Core ML predictions on long-lived threads must free their results per call (`autoreleasepool` in `SpeakerSegmentationModel.frameClasses` and `PunctuationModel.predictions`): without it `SpeakerPass` grew ~2.4 GB per 21 minutes (5 GB peak for 54 min); now ~0.6–0.8 GB whatever the length. `.work/sealed-test` (5 EMpodcat episodes, 53,500 words, never used for tuning) is the held-out check: 11.26% → 11.16% WER after the 2026-09-30 audit; beam search was tried and made it worse (more insertions).

- Subtitle editor (2026-10-10): when a video's transcription finishes with words, the editor opens by itself (Mac `ContentView`, iPhone `PhoneReaderView`, on `imports.current?.phase`); the finished import card leads with "Revisa i corregeix" to open it again (Mac also Arxiu › Revisa els subtítols ⌘R), which opens `SubtitleEditorView` (shared; Mac: a full-window layer over `ContentView`, film left and lines right; iPhone: a large sheet, film on top). `SubtitleDocument` (SubtitolCore) groups the session's words into lyric-like lines (≤ 42 characters; breaks at paragraphs, sentence ends, pauses ≥ 0.7 s, 7 s, preferably after a comma) and retimes a corrected line by a longest common subsequence of case/accent/mark-free words: kept words keep their times, new words share the replaced words' time by length. `SubtitleEditorModel` plays the video (`AVPlayer`, a 30 Hz `PlaybackClock` so only the current line, the scrubber and the preview redraw), lights the current line word by word, and a tapped line plays once while it is edited in place (↩ keeps, ⇥ next, esc drops, Space/←/→ when not typing; its own undo/redo history, which the Mac's Edit menu reaches while the editor is open, with Cut/Copy/Paste/Select All for the field). A line being corrected also has (2026-10-17) four round keys beside Escolta: split at the cursor (or where the line reads best, `SubtitleDocument.naturalSplit`, when the cursor is at an end), join with the next line, add a line the recogniser missed into the silence after it (`gap(after:)`, ≥ 0.3 s; typed in a row of its own, `SubtitleEditorModel.Insertion`, id -1, added only if not left empty) and delete; each is one undo step (`change(_:)`).
